Lightweight Infrastructure Automation Portal

Architectural Specification & Operational Guide for the streamlined, non-ITSM self-service portal.

⚡ Core Architectural Principle: Basic & Lightweight by Design

This portal was built as an independent, lightweight feature branch that reuses the React/Tailwind visual foundation while completely stripping away enterprise ITSM baggage (RabbitMQ queues, PostgreSQL clusters, dead-letter exchanges, BMC Helix/ServiceNow webhooks, and incident/change ticket lifecycles). It provides a direct 4-step user experience: Select Automation → Input SID → Single Approver Review → Trigger Existing GitHub Actions Workflow.

3 Single Designated Approver & Permission Resolution

🛡️ Understanding "Permission denied: Only designated approvers can approve requests"

To prevent unauthorized execution of production infrastructure changes (e.g., stopping SAP HANA databases or Oracle clusters), the portal strictly enforces Separation of Duties via a Single Designated Approver mechanism.

👷 Engineer Role (engineer_user)

The default requesting user. Can browse the catalogue, submit requests with required SID and parameters, and view execution tracking. Cannot approve their own or any other request.

🔑 Approver Role (approver_user)

The designated approver configured in config.py. Has the cryptographic authorization to approve or reject pending requests, which automatically triggers the GitHub Actions dispatch.

How to resolve in the UI:
On the Approvals Workbench (/portal/approvals) or sidebar, click the green "Switch to Approver Role" button. The portal will immediately update your session header to X-Portal-User: approver_user, allowing 1-click approvals.
